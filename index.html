今天要做什麼？

班守把兩件事分開做：排班是事前把班表排好、排合法；替班是臨時有人請假時，快速找到合法又公平的替補。從下面選一個開始。

人力缺口總覽

缺工不是「感覺人不夠」，是一筆可以算的帳：營運所需人力 − 可合法且合理排入的人力 ＝ 實際人力缺口。這一頁把缺口變成可量化、可追蹤、可行動的管理資訊——缺在哪、缺多少、吸收後剩多少、是偶發還是結構性。

能力與出勤儀表板

兩種徽章、兩個問題：資格徽章回答「有沒有人會做」，進階徽章（N1–N4／AHN）回答「有沒有人扛得住」。三班的實力要平衡——白天資深扎堆、夜裡新人獨撐，就是這一頁要抓出來的事。

缺班事件建立

兩條路建立缺班事件：快速通報直接在班表上點出缺班的人——人、日期、班別、單位零輸入；或把請假訊息貼給 Agent 解析。可多選：一次點出多筆缺班，交給全局指派一起找替補。

主管確認摘要

Agent 只提供建議，正式調班仍由授權主管決定。通知一律停在草稿，系統不會自動發送給員工，也不會寫入正式班表。

請先在「替補候選人」頁選定人選。

公平性儀表板與決策留痕

替補不只要快，還要交代得出「為什麼是他」。這一頁把風險預警、分配狀況與每一次決策攤在陽光下。

主動預警：本週班表掃描

掃描中

預警來自規則引擎對「已排定班表」的靜態掃描——不等有人請假才發現風險。 門檻與規則庫連動（H4／H5／H6／公平性飽和），主管確認替補寫回後即時更新。

近 30 天被叫班替補次數

分配愈平均愈健康

匯出內容含全部操作紀錄與當前規則設定，可作為決策依據的留存檔。正式導入時將由後端以不可竄改方式儲存。

多筆缺班：逐筆指派 vs 全局指派

流感季一個晚上倒兩個人是常態。逐筆處理會把稀缺人力提早用掉；全局指派把所有缺班一起看——先求填補筆數最多，再求整體分數最高。兩種算法都是確定性運算，逐一比較給主管看。

演示情境：同一晚兩筆缺班

以目前班表即時計算

情境重點：全院只有一位人員具備呼吸器照護資格，而他同時是第一筆缺班的最高分候選——考驗系統會不會把稀缺人力用錯地方。

第三層：連替補都無解時——任務重新分配

韌性模式

假設情境：上方 ICU 那筆缺班，連唯一具呼吸器照護資格的 N-10 也請假——全院無人可替補。 此時缺的不再是「一個人」，而是「一班的任務」： 把缺班者的任務拆解，重分配給在班人力；資格硬性匹配、負荷平衡， 無人可承接的任務誠實標示為缺口，交主管啟動上報或調度。

班表生成：第 0 層源頭治理

缺班替補做得再好，都是事後補救。把同一套 H1–H6 規則放進排班源頭，讓班表「排出來的那一刻」就合規——下游的替補、放寬、任務重分配，被觸發得越少越好。

生成條件：下一週人力需求

門檻與規則庫連動

生成使用與缺班替補完全相同的一份 H1–H6 檢查程式碼與規則庫參數； 現有班表作為邊界條件——週日大夜的殘影（H4）、跨週的連續上班天數（H5）都會約束下週的生成。 到「規則庫」調整門檻後重新生成，班表會跟著改變。

FHIR 介接（HL7 FHIR R4／TW Core IG）

衛福部正以 FHIR 與台灣核心實作指引（TW Core IG）作為醫療資訊交換的推動標準。這一頁把班表轉成 Practitioner／Schedule／Slot 等標準資源與院內系統對接：匯出成檔、推送至 FHIR Server、或把外部系統的班表匯入本平台——匯入一律經白名單驗證，不合法逐筆報告、不套用。
