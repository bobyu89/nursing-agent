## 發現與處置

嚴重度定義:High＝可導致錯誤決策數字或可被利用的注入;Medium＝特定條件下才觸發或屬縱深防禦缺口;Low＝體驗與衛生問題。

### 已修復（本次）

| 編號 | 嚴重度 | 類別 | 發現 | 修復 |
|---|---|---|---|---|
| F-1 | High | 功能 | 日期輸入只驗格式不驗真實性：「2026-02-31」通過 `YYYY-MM-DD` regex，但 JS Date 自動進位成 3/3；引擎內字串比對（H2、週工時）與日期運算各算各的，**工時與班距可能算在錯的日子上**——在本平台屬合規事故等級 | 新增 `isValidDateStr()` 嚴格日曆驗證（engine.js），用於：追問表單送出（app.js）、mock 解析的 M/D 線索（llm.js，不合法即轉追問）、`completeGapEvent` 最後閘門 |
| S-1 | High（僅 api 模式） | 資安 | api 模式的模型回應只驗「形狀」不驗「值」：通報訊息是不可信輸入（可夾帶 prompt injection），模型吐回的 `extracted.date.value` 等值未經白名單即進入引擎與畫面 | 新增 `sanitizeParsed()`：日期／班別／單位／資格逐欄白名單驗證，label/source 截長；不合法值降級為「未解析→追問」，與不臆測原則一致 |
| S-2 | Medium | 資安 | 追問表單的日期欄位 `value="${v...}"` 未跳脫——搭配 S-1，模型控制的值可造成屬性注入 XSS | 補 `esc()`；並以 S-1 在源頭消毒（縱深防禦） |
| S-3 | Medium | 資安 | `loadRules()` 從 localStorage 載回的數值未夾限：H4 班間休息被塞成 0 或負數＝**無聲關閉法定下限檢查**（devtools 或同源程式即可改寫） | 新增 `PARAM_RANGE`／`WEIGHT_RANGE` 逐值夾限（H4:0–24、H5:1–14、H6:8–168、S1:1–99、S2:8–168、權重 0–50，與 UI 滑桿一致） |
| S-4 | Medium | 資安 | 無 CSP、無 referrer policy | `index.html` 加入 CSP（同源限定，含 `file:` 保留雙擊離線流程；`connect-src` 保留 https 供 api 模式）＋ `referrer: no-referrer` |
| S-5 | Medium | 資安／可用性 | `llmCallApi` 無傳輸層要求也無逾時：endpoint 可為 http 明文；端點無回應時 fetch 永久懸掛，解析按鈕卡死 | 強制 https（localhost 例外）＋ AbortController 15 秒逾時，逾時走既有 fallback 退回 mock |
| F-2 | Medium | 功能 | `handleParse` 無重入保護、無 try/finally：貼上事件與點擊可重疊觸發互相覆蓋畫面；解析中途拋錯則按鈕永久停在「解析中…」 | 加入 `parsing` 旗標與 try/finally，按鈕保證回復可用 |
| F-3 | Low | 功能 | 「處理下一筆缺班」未清除上一筆的規則重算結果，殘留過期資訊 | `startNextGap` 一併清空 `#recalc-result` |
| S-6 | Low | 資安（縱深） | 候選人／排除名單／班表／人員主檔／規則庫渲染的 `staff.id`、`role`、單位、規則文字未跳脫——目前是本地靜態資料無風險，但正式導入改後端供資後即成注入面 | 主要渲染路徑全面補 `esc()` |
