## 上場前 5 分鐘檢查清單

1. 雙擊 `tests.html` → 必須顯示「✓ 全數通過（151 項）」。紅的就不要上場，先修。
2. 開 `home.html`（或 GitHub Pages 首頁）確認 Landing 正常、影片有動。
3. 進平台後右上角標示「LLM 模式：模擬（離線）」→ 主線整場不需要網路（只有 LINE 幕需要）。
4. 到「班表工作區」按**還原示範班表**、到「規則庫」按**還原預設規則**（權重回 30/25/20/15/10），
   然後**重新整理一次**——留痕歸零、演示狀態乾淨。前次演練的任何寫回都會殘留在 localStorage，這步不能省。
5. 若剛部署過新版：**Ctrl+F5** 強制重載，避免瀏覽器快取舊檔。
6. 手機：LINE 對話（@913sepht）先開好、圖文選單有出現；投影前先自己按一次「儀表板」暖場確認回覆正常。
7. 身份切到**護理長**（側欄上方切換器）——主線台本以護理長視角寫成；
   壓軸想演「身份隔離」再現場切督導／護理師。
8. 斷網備案：LINE 幕直接跳過——換班預檢與戰情儀表板在平台端都有同功能，台詞改「LINE 版是同一份引擎，回去掃 QR 就能玩」。

## 壓軸：多筆缺班與韌性模式（1.5 分鐘，回答「這不就是個篩選器嗎」）

到「多筆與韌性」頁，唸情境：同一晚兩筆缺班，**全院只有 N-10 會呼吸器，他同時是第一筆的最高分**。

- 按「執行兩種指派方式並比較」：逐筆指派→第二筆**無人可指派**；全局指派→N-01 補第一筆、
  N-10 留給 ICU，**兩筆都補上**。台詞：「逐筆最佳不等於整體最佳——這是需要引擎而不是篩選器的原因。」
- 往下捲紅框卡：「那如果 N-10 **也倒了**呢？」按模擬 → 任務重分配覆蓋 4/6 項、
  兩人負荷 3/3 達上限；**兩項缺口誠實攤開**（呼吸器監測＝無人具資格；口服給藥＝量能不足）＋三個升級選項。
  台詞：「系統不假裝問題解決了。護理長拿到的不是『無解』，是一份把**還能做什麼**與
  **還缺什麼**同時攤開的降級方案。需要資格的任務寧可標成缺口也不亂塞人——這在 ICU 是病安底線。」

收：這一頁由上而下就是決策階梯第 1→2→3 層，層層有據、層層留痕。

## 三個現場挑戰的應對

**① 評審要求自己改寫訊息。** 歡迎。四個範例訊息一鍵帶入；LINE 貼上也會解析。
安全示範句：「我下週三大夜要去進修」→ 8/19 大夜＋追問；「我不能上班了」→ 四項全部轉追問、一項不猜。
隱藏加分題：訊息同時含兩個時間線索（「我從**今天**開始發燒，**禮拜天**的班沒辦法上」）
→ Agent 偵測到衝突、不猜、列出所有線索轉追問——「不臆測」的最佳現場證明。

**② 「如果找不到人呢？」** 資格全勾或單位改 ICU → 候選不足時列出「放寬哪條會多出誰」的試算，
並區分：H3 可徵詢意願；H4–H10 涉法規病安，只供了解成因，**Agent 不自行放寬**。
再追問「放寬也沒人呢？」→ 升級路徑卡片末端就有「**前往第 3 層：任務重新分配 →**」，
按下去直接落在韌性模式。這一題用「現場按給你看」回答。

**③ 「連 6 天、60 小時是法規嗎？」**（懂勞動法的評審）現在的標準答案更硬：
班間 11 小時（H4）是法定下限；**H7–H9 就是勞基法第 30 條之 1 四週彈性工時本文**
（雙週例假、四週 160 小時總量、四週例假＋休息日 8 日），已入硬規則、貫穿替補／換班／生成；
H5、H6 是以法規為底線、比法規更嚴的院內治理政策，做成規則庫可調參數而不是寫死的假設。
細節在 `docs/CONTEXT.md`。

## 常見 Q&A

- **「Excel 做不到嗎？」** → 兩個現場證據：N-07（篩「當天沒班」會選到大夜剛下班 0 小時的人）、
  換班紅燈（兩張班表各自合法、交叉才違法）。
- **「這是真的 AI 嗎？」** → 誠實聲明：現場跑 mock（右上角有標），關鍵詞真的在比對；
  數字的部分**刻意不用模型**——算錯工時是合規事故，不是體驗瑕疵。
- **「能接醫院現有系統嗎？」** → FHIR R4 對齊 TW Core IG，對 HAPI 公開沙盒實測 80/80 筆成功；
  匯入有白名單驗證。這是「進得了醫院」的工程證據。
- **「資安？有人亂搞你的 LINE bot 怎麼辦？」** → 四層：簽章驗證（偽造請求 403）→
  使用者白名單 → 頻率限制（洪水自動靜默）→ 管理員即時告警；平台端 localStorage 竄改
  有白名單驗證與安全警示留痕。完整應對手冊在 `docs/SECURITY.md`（含金鑰 3 分鐘輪換流程）。
- **「權限怎麼管？護理師會不會亂改班表？」** → 現場切給他看：三種身份三條工作流，
  護理師唯讀、寫回動作只在護理長視角；護理師談好的互換可**送單**進佇列，
  但核准寫回仍在護理長（送單不改班表，核准才改）；督導主任可**檢視**護理長全流程
  （上級看下級）但結案／核准／套用顯示檢視模式。示範用切換無登入，正式導入接院內 SSO，每次切換留痕。
- **「病人資料？」** → 全虛構、全代號，系統設計上不接觸病歷；LINE 圖表純 JSON，資料不經第三方。
- **「為什麼不自動發通知？」** → 治理原則：Agent 建議、人決定。草稿停在草稿是功能，不是缺陷。
- **「功能太多，第一次用會不會迷路？」** → 現場開給他看：側欄底部「🎓 新手教學」——
  六步帶完一筆缺班的完整治理迴路，**做完一步才解鎖下一步**（其餘畫面上鎖），
  **守守會蹦跳到該點的按鈕旁邊指路**、按鈕發光。首次進站自動邀請；評審拿手機掃 QR 也會被接住。
- **「手機能用嗎？」** → 能：LIFF 讓平台在 LINE 內全螢幕開啟，介面是抽屜式行動版；
  但主管簽核的主場景仍設計在桌機——這是刻意的產品判斷，不是技術限制。
