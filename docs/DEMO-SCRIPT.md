# DEMO DAY 台本

以下所有畫面數字都以**預設資料 + 預設規則**為準，並已在瀏覽器實測過。
若前一次演練調過規則，上場前務必按「還原預設規則」。

## 上場前 5 分鐘檢查清單

1. 雙擊 `tests.html` → 必須顯示「✓ 全數通過（31 項）」。紅的就不要上場，先修。
2. 雙擊 `index.html` → 右上角標示「LLM 模式：模擬（離線）」。整場不需要網路。
3. 到「規則庫」按**還原預設規則**（若按鈕彈出確認就按確定）→ 權重回到 30/25/20/15/10。
4. 重新整理一次頁面 → 班表寫回與留痕歸零，演示狀態乾淨。
5. 不要現場切 api 模式。就算切了，任何呼叫失敗都會自動退回 mock 並在右上角標示，演示不會中斷。

## 開場 30 秒

> 醫院班表排定後還是會臨時缺人。真正難的不是快——是「為什麼找他不找我」說不清楚。
> 找人的標準只存在護理長腦子裡，結果就是誰好講話就一直找誰，而這是護理離職的真實原因之一。
> 班守做的事：幾秒內給出合格替補與排序理由，而且**每一個判斷都交代得出依據**。

## 加演：同日第二筆缺班（治理迴路是閉合的）

第一筆確認後，按主管確認頁的「**處理下一筆缺班 →**」（狀態自動重置，班表與公平性延續），
把訊息改成：

> 護理長，我發燒到 38 度，禮拜天的小夜沒辦法上了，真的很抱歉

- 通報人員選 **N-06**；資格**只勾 ACLS**（小夜當天沒有化療給藥）。
- 台詞：「剛才指派的 N-02 現在怎麼樣了？」
- 預期畫面：**N-02 出現在不推薦名單，理由 H2「當日已排 白班（07:00–15:00）」**——
  剛寫回的替補班次立刻參與下一次決策；公平性頁 N-02 的次數也已 +1。
- 新的合格排序：N-08（75.2）> N-03（65.5，只要 ACLS 他就合格了）> N-10（34.5）> N-01（28.5）。
- 收在公平性頁，三個順手可指的點：
  1. 上方「**主動預警**」：N-09 連六天達上限（再排一天即違規）、48 小時達軟性上限、
     N-01 再被叫一次就達公平性飽和——台詞：「**系統不等有人請假才動**，
     班表排下去的那一刻，風險就已經被掃出來了。」
  2. 中間的**平均／最高／最低／差距**摘要。
  3. 按「**匯出 JSON**」——台詞：「勞檢或內部稽核時，每一筆決策的依據和
     當時的規則設定，一鍵拿得出來，而且留痕是雜湊鏈結的，改任何一筆都會被抓到。」

> 💡 隱藏加分題：如果評審輸入同時含兩個時間線索的訊息
> （例：「我從**今天**開始發燒，**禮拜天**的班沒辦法上」），
> Agent 會偵測到多個時間線索指向不同日期，**不猜哪一個是缺班日、直接轉為追問**，
> 追問欄會列出它看到的所有線索。這是「不臆測」原則的最佳現場證明，可以主動演。

## 進階幕：多筆缺班（回答「這不就是個篩選器嗎」）

到第 7 頁「多筆缺班」，先唸情境：同一晚兩筆缺班——內科白班要資深帶化療、
ICU 小夜要會呼吸器的人，而**全院只有 N-10 會呼吸器，他同時是第一筆的最高分候選**。

按「執行兩種指派方式並比較」：

- 左欄（逐筆指派）：第一筆選了 N-10（69.5 分，比 N-01 的 63.5 高）→
  **第二筆 ✗ 無人可指派**。每一步都「對」，整體卻補不滿。
- 右欄（全局指派）：第一筆改用 N-01、N-10 留給 ICU → **兩筆都補上**。

台詞：「Excel 篩得出名單，甚至寫個腳本也能逐筆挑最高分——但一到多筆缺班，
逐筆最佳不等於整體最佳。這是排班治理需要引擎、而不是篩選器的原因。」
補一句誠實聲明：指派建議仍需主管逐筆確認才會寫回，Agent 不代替主管決定。

## 壓軸幕：韌性模式（回答「如果連人都找不到呢」）

全局指派把兩筆都補上之後，往下捲到同一頁的紅框卡片，先唸假設：

> 那如果連唯一會呼吸器的 N-10 **也倒了**呢？全院無人可替補——
> 缺的不再是「一個人」，是「一班的任務」。

按「模擬：唯一合格者也倒下，啟動任務重分配」：

- **重分配方案（覆蓋 4/6 項）**：I-01（具 IV 資格）接下**中央靜脈導管給藥**＋護理紀錄與交班準備；
  I-02 接下**生命徵象與意識評估**＋家屬溝通與衛教。兩人負荷都達 **3/3 點上限**，
  畫面同時顯示照護風險警告。
- **兩項關鍵缺口誠實攤開，而且原因不同**：
  呼吸器參數監測與抽痰 → **無人具必要資格**；常規口服與管灌給藥 → **在班人力量能不足**。
- 缺口下方列出三個主管決策選項：上報院級調度、跨區支援、非緊急任務延後。

台詞：「系統沒有假裝問題解決了。它不會自動刪任務、不會自動降載——
護理長拿到的不是『系統無解』四個字，而是一份把**還能做什麼**與**還缺什麼**
同時攤開的降級運作方案。需要資格的任務，寧可標成缺口也不亂塞人——這在 ICU 是病安底線。」

收這一幕：這一頁從上往下就是完整的**三層決策階梯**——
找合格替補 → 放寬試算＋全局指派 → 任務重新分配。層層有據、層層留痕。

## 三個現場挑戰的應對

**① 評審要求自己改寫訊息。** 歡迎。輸入框上方有四個**範例訊息**（典型病假／下週進修／
日期模糊／什麼都沒說），點了直接帶入並解析——不用現場打字。從 LINE **貼上訊息也會自動解析**。
安全示範句：「我下週三大夜要去進修」→ 8/19 大夜、進修、追問單位與資格；
「下下禮拜三」也能正確推算（+14 天）；「我不能上班了」→ 四項全部轉追問、一項都不猜。

**② 「如果找不到人呢？」** 把必要資格四項全勾（或單位改 ICU）再評估——候選人不足 3 位時，
系統列出「放寬哪一條會多出誰」的試算，並區分：H3 可由主管徵詢意願、H4/H5/H6/H1 涉及
法規與病安，只供了解缺口成因。台詞：「**Agent 不會自行放寬任何規則**，它只把選項和代價
攤開，決定權在主管。」
若評審再追問「**放寬也沒有人呢？**」——不用口頭解釋，直接切到第 7 頁按下韌性模式
（見壓軸幕）。這一題，用「現場按給你看」回答，比任何台詞都有力。

**③ 「連 6 天、60 小時是法規嗎？」**（懂勞動法的評審會問）標準答案在 `docs/CONTEXT.md`：
H4 班間 11 小時是法定下限；H5、H6 是**以法規為底線、比法規更嚴的院內治理政策**——
變形工時制度下法定要求更複雜，所以我們把它做成規則庫裡可調的參數，而不是寫死的假設。

## 常見 Q&A

- **「Excel 做不到嗎？」** → 回到 N-07：Excel 篩「當天沒班」會選出一個大夜剛下班 0 小時的人。
- **「這是真的 AI 嗎？」** → 誠實聲明：現場跑 mock（右上角有標），關鍵詞真的在比對、不是預錄；
  數字的部分本來就**刻意不用模型**——算錯工時是合規事故，不是體驗瑕疵。
- **「病人資料？」** → 全虛構、全代號，系統設計上不接觸病歷。
- **「為什麼不自動發通知？」** → 治理原則：Agent 建議、人決定。草稿停在草稿是功能，不是缺陷。
