# DEMO DAY 台本

以下所有畫面數字都以**預設資料 + 預設規則**為準，並已在瀏覽器實測過。
若前一次演練調過規則，上場前務必按「還原預設規則」。

## 上場前 5 分鐘檢查清單

1. 雙擊 `tests.html` → 必須顯示「✓ 全數通過（14 項）」。紅的就不要上場，先修。
2. 雙擊 `index.html` → 右上角標示「LLM 模式：模擬（離線）」。整場不需要網路。
3. 到「規則庫」按**還原預設規則**（若按鈕彈出確認就按確定）→ 權重回到 30/25/20/15/10。
4. 重新整理一次頁面 → 班表寫回與留痕歸零，演示狀態乾淨。
5. 不要現場切 api 模式。就算切了，任何呼叫失敗都會自動退回 mock 並在右上角標示，演示不會中斷。

## 開場 30 秒

> 醫院班表排定後還是會臨時缺人。真正難的不是快——是「為什麼找他不找我」說不清楚。
> 找人的標準只存在護理長腦子裡，結果就是誰好講話就一直找誰，而這是護理離職的真實原因之一。
> 班守做的事：幾秒內給出合格替補與排序理由，而且**每一個判斷都交代得出依據**。

## 加演：同日第二筆缺班（治理迴路是閉合的）

第一筆確認後，回第 1 頁把訊息改成：

> 護理長，我發燒到 38 度，禮拜天的小夜沒辦法上了，真的很抱歉

- 通報人員選 **N-06**；追問的資格**只勾 ACLS**（小夜當天沒有化療給藥）。
- 台詞：「剛才指派的 N-02 現在怎麼樣了？」
- 預期畫面：**N-02 出現在不推薦名單，理由 H2「當日已排 白班（07:00–15:00）」**——
  剛寫回的替補班次立刻參與下一次決策；公平性頁 N-02 的次數也已 +1。
- 新的合格排序：N-08（75.2）> N-03（65.5，只要 ACLS 他就合格了）> N-10（34.5）> N-01（28.5）。

> ⚠ 訊息文案不要包含「今天／明天」等字眼——mock 解析依關鍵詞優先序，
> 「我從**今天**開始發燒，**禮拜天**的班……」會先命中「今天」而抓錯日期。
> 真的被評審弄出來也不慌：指著「依據」欄位說明它抓了哪個詞，改寫訊息重新解析即可——
> 這正是「每個欄位都標示出處」的價值。

## 三個現場挑戰的應對

**① 評審要求自己改寫訊息。** 歡迎。安全示範句：「我下週三大夜要去進修」→ 8/19 大夜、進修、
追問單位與資格；「下下禮拜三」也能正確推算（+14 天）；「我不能上班了」→ 四項全部轉追問、
一項都不猜。地雷見上方警告框。

**② 「如果找不到人呢？」** 把必要資格四項全勾（或單位改 ICU）再評估——候選人不足 3 位時，
系統列出「放寬哪一條會多出誰」的試算，並區分：H3 可由主管徵詢意願、H4/H5/H6/H1 涉及
法規與病安，只供了解缺口成因。台詞：「**Agent 不會自行放寬任何規則**，它只把選項和代價
攤開，決定權在主管。」

**③ 「連 6 天、60 小時是法規嗎？」**（懂勞動法的評審會問）標準答案在 `docs/CONTEXT.md`：
H4 班間 11 小時是法定下限；H5、H6 是**以法規為底線、比法規更嚴的院內治理政策**——
變形工時制度下法定要求更複雜，所以我們把它做成規則庫裡可調的參數，而不是寫死的假設。

## 常見 Q&A

- **「Excel 做不到嗎？」** → 回到 N-07：Excel 篩「當天沒班」會選出一個大夜剛下班 0 小時的人。
- **「這是真的 AI 嗎？」** → 誠實聲明：現場跑 mock（右上角有標），關鍵詞真的在比對、不是預錄；
  數字的部分本來就**刻意不用模型**——算錯工時是合規事故，不是體驗瑕疵。
- **「病人資料？」** → 全虛構、全代號，系統設計上不接觸病歷。
- **「為什麼不自動發通知？」** → 治理原則：Agent 建議、人決定。草稿停在草稿是功能，不是缺陷。
