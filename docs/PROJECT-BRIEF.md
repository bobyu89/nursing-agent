## 一、Brief 正文

**班守 ShiftGuard｜專案 Brief**
一年內完成規則確認、唯讀試行、平行驗證與分批上線；本頁供提案討論，不代表院方已承諾。

### 問題與目標

**現況問題**
排班須同時滿足人力配置、證照效期、勞基法工時（含四週彈性工時）與個人限制；
臨時缺班靠人情打電話，換班合不合規靠主管肉眼判斷。
這些違規與過勞不會出現在任何報表——只會出現在勞檢紀錄和離職單上。

**導入目標**
讓每一次人力調度都交代得出「為什麼是他」：規則引擎負責算（工時、班距、資格、法規），
主管負責決定，每一步留痕可稽核。最終核准與正式登錄仍由院方人員負責。

**第一階段使用者**
單一內科病房的護理長與該病房護理師（全員 LINE 綁定、線上送預假）；督導／護理部以檢視視角參與。

### 第一步方案

| 欄位 | 提案內容 |
|---|---|
| **AI 協助** | 產品已能完整寫回，試行**刻意分段開啟**：第一步只開**收集與建議**——LINE 一句話通報缺班 → 合格替補前三名（附每一位被排除的原因）；換班簽核前預檢（互換後兩人各自重跑 H1–H10）；全員線上預假。預班草稿在平行期保留不公告，只與人工班表對照；驗收通過後才開寫回（核准並公告、替班逐一詢問） |
| **人工負責** | 護理部核定規則庫參數；人資核定勞基法門檻（H4–H10）；每一筆替補與換班由護理長逐項勾選確認後核准；正式登錄仍在院內系統 |
| **試行範圍** | 單一病房；只碰人員代號、資格與班表，**不接觸任何病人資料**；平行運作、不寫入正式班表；院內部署，資料不出院。七維度完整界定（時間／使用者／案件／事件／環境／成本／代價）見 [PILOT-SCOPE.md](PILOT-SCOPE.md) |
| **預期成果** | 可量化五項：引擎掃描人工班表的 H1–H10 違規條數；一筆缺班從通報到核定的時間；代班次數分布的公平性；夜班／連續上班負荷旗標數；預假準時回收率 |
| **現在的請求** | 指定護理部與資訊室窗口；提供規則清單（工時、班距、資格門檻、院內政策）與近三個月班表 Excel（範例格式可直接下載填寫）；核定試行病房 |

**範圍外**：自動發布班表、取代主管判斷、接觸病歷資料、未經驗收的全院上線。

## 二、跟老師模板的差異（每一格為什麼要改）

| 模板寫法 | 班守寫法 | 為什麼 |
|---|---|---|
| 現況問題：「異動時需要大量人工重排與溝通」 | 「違規與過勞不會出現在報表，只會出現在勞檢紀錄和離職單上」 | 模板講的是**操作痛**（麻煩），班守要講**治理痛**（合規、留任）。對護理長「省時間」是好事，對主任「勞檢不被開單、人不會走」才是簽字的理由 |
| AI 協助：「產生初版班表」放第一 | 第一步只開收集與建議（替補建議、換班預檢、線上預假），生成草稿平行期只對照 | 模板把最高風險的功能放最前面。班守產品已能完整寫回，試行刻意分段開——主動收斂比能力不足可信；預假收集不改任何班表、護理長第一天就能用，還給了全單位綁定的理由 |
| 人工負責：「確認法規、院內規範、資格與臨床需求」 | 法規門檻**內建、可調、每條附法源**，人資只需核定參數 | 模板把法規當成人工的負擔；班守把它當成產品的一部分。勞基法 30-1 四週彈性工時、49 條母性保護都已在規則庫裡 |
| 試行範圍：「去識別資料」 | 「不接觸任何病人資料」 | 去識別是「有碰、但遮掉」；不接觸是「根本不碰」。班守只碰人員代號與班表，資安審查的難度差一個量級——這是 BLUEPRINT 寫死的邊界 |
| 預期成果：「降低規則衝突；保留人員滿意度」 | 五項可量化指標 | 「降低」「保留」是方向不是數字。違規條數、處理時間、公平性分布、負荷旗標數、預假回收率都是系統現在就算得出來的，驗收時直接對照 |
| 現在的請求：「提供規則清單及歷史班表」 | 加上「範例格式可直接下載填寫」 | 班表工作區已支援 .xlsx／.csv 匯入與範例檔下載，把「怎麼給」的摩擦一起解掉 |
| 範圍外三項 | 加「接觸病歷資料」 | 主動把院方最怕的事寫進範圍外，資安與個資審查會快很多 |

模板沒有、班守要補進去的四個差異化：**LINE 通報入口**（零學習成本）、**法規內建**、
**不碰病人資料**、**雜湊鏈留痕**（勞檢與評鑑一鍵舉證）。這四個都在 Brief 正文裡了。
